## 1. 产品定义

### 1.1 一句话定位

**Octop 是一个自托管（self-hosted）的多用户、多专家 AI 助手平台**——单进程启动，
同时提供 Web 控制台、原生桌面客户端、CLI、HTTP/WebSocket API 与 IM 通道接入，
面向团队、家庭与个人，强调数据留在自己的机器上。

### 1.2 产品愿景

让用户拥有一套**独立且可协作**的「数字生命体」环境：每个专家有独立人格、工作区与
记忆，既能并行工作，也能通过 AgentTeams 协作完成多步骤任务；既能在本地完整运行，
也能按需把重活交给云端。

### 1.3 产品定位的分化（关键）

当前产品线实际上分化成**两个互补的产品面**，需求取舍必须按面区分，不能混为一谈：

| 产品面 | 定位 | 面向用户 | 交互形态 | 代表功能 |
|---|---|---|---|---|
| **通用助手平台**（Web / CLI / 桌面通用模式） | 完整的 Agent 控制台 | 开发者、进阶用户、管理员 | 专家/团队/云端多分组、模型配置、连接器、插件 | 创建专家、ACP、知识库、通道、定时任务 |
| **素材与视频专用应用**（桌面精简模式） | 面向素材管理与视频生成的专用工具 | 内容创作者、电商运营 | 单一对话框 + 产品素材库，不暴露通用控制台 | 目录导入 AI 识别、产品视频向导、配音配乐 |

> 这一分化是 [桌面端「直接对话框」改造](./desktop-direct-chat-panel.md) 的根本依据：
> 桌面端正在从「通用控制台」收敛为「专用应用」，**浏览器端行为保持不变**。

## 2. 目标用户与场景

| 用户画像 | 核心诉求 | 主要入口 | 关键场景 |
|---|---|---|---|
| **内容创作者 / 电商运营** | 把商品图片批量变成产品视频 | 桌面精简模式 | 目录导入素材 → AI 自动分组 → 选曲配音 → 五步向导出片 |
| **团队 / 家庭管理员** | 一套共享、可隔离的 AI 助手 | Web 控制台 | 多用户多专家、权限与页签勾选、专家共享 |
| **开发者 / 进阶用户** | 可编程、可嵌入的 Agent 能力 | CLI / API / ACP | `octop acp`、HTTP/SSE/WS、委派给 OpenCode/Claude Code |
| **IM 重度用户** | 在聊天软件里驱动 AI | IM 通道 | 飞书/钉钉/QQ/微信/企业微信、定时任务主动推送 |

### 2.1 核心用户旅程（专用应用面）

```
登录（扫码 SSO） → 自动获得默认助手（R1/R2）
    → 直接进入可输入的对话框（R3/R4，无「创建专家」墙）
    → 素材库目录导入 → 服务端调用远程多模态模型 AI 分组（见导入架构文档）
    → 选取素材 → 产品视频向导 → 配音/配乐 → 确认分镜 → 导出
```

该旅程的每一步都有对应的需求条目与既有专题文档，见 §4 与 §10。

## 3. 产品能力全景

能力按层组织，与 [架构分层](./architecture.md#1-layering) 对齐：

### 3.1 助手与专家
- 每用户可建多个专家，各自独立工作区、供应商、通道、定时任务
- 16 种 MBTI 人格模板 + 自定义系统提示词
- 专家库扫描、专家市场、同实例专家共享
- **AgentTeams（Beta）**：协调者 + 成员专家协作
- 默认助手引导：新账号（含 SSO）自动获得 `general-assistant`

### 3.2 素材与视频（专用应用核心）
- **产品素材库**：按用户隔离的素材管理；目录导入由**服务端**调用远程多模态模型识别分组
  （权威结论见 [导入架构](./product-library-import-architecture.md)，客户端不跑模型）
- **产品视频创作**：五步向导、LLM 生成分镜、草稿编辑确认、导出 ZIP
- **配音**：免费档 Windows SAPI 本机合成 / 付费档服务端 MiniMax，失败按免费档降级
- **配乐**：24 首曲库、试听与 BPM 搜索、时长按小节吸附；曲库不随客户端分发

### 3.3 连接与自动化
- IM 通道：飞书、钉钉、QQ、微信、企业微信、Telegram、Discord 等
- 连接器（OAuth + MCP）、知识库 RAG、插件系统
- 主动定时任务（自然语言 / 斜杠命令触发）
- **ACP 双向**：入站为 IDE 提供 ACP 服务，出站委派给外部编程 Agent

### 3.4 认证与安全
- 多用户 JWT、管理员角色、首次运行向导
- SSO（微信开放平台扫码等）、LDAP、邀请码
- 工具审批、shell 命令护栏、PII 脱敏、按页签权限勾选

### 3.5 多端入口
- Web 控制台、原生桌面客户端（Win/macOS/Linux）、CLI、HTTP/SSE/WebSocket API、远程桌面

### 3.6 补充优化：本地质检基础图库（2026-11-20）

> 状态：**已实现**（代码基线见 §9）。本节是对 §3.2「素材与视频」的补充，不改变
> 「目录导入 AI 识别由服务端调用远程模型」的既有职责边界——基础图库是**另一条入口**，
> 只做本地确定性质检，不调用任何模型。

**要解决的问题**：目录导入把每一张上传的图都送远程多模态模型，坏图/差图/重复图同样烧调用；
用户缺少一个「挑过的、可直接批量出片」的干净图源。

**产品定义**：新增「基础图库」——由本地 PIL + numpy 质检筛出的高质量图片池，SQLite 索引，
按用户隔离；坏图/差图/重复图统一进入隔离区，用户处理后只保留干净图，未来可直接由此批量生成视频。

| # | 产品需求 | 用户可感知结果 | 实现状态 |
|---|---|---|---|
| **B1** | 上传即本地质检（解码/EXIF/尺寸/清晰度/曝光/纯色/哈希） | 垃圾图不再占用远程识别；无模型等待 | ✅ 已实现 `POST /product-library/base-library/ingest` |
| **B2** | 坏图/差图/重复图隔离到统一目录 | 一个 `quarantine/` 目录即可整体查看与清理，好图在 `base-library/` | ✅ 已实现（按 reason 分子目录） |
| **B3** | SQLite 记录质检元数据与状态 | 可按质量分/来源/状态筛选，重启不丢；按用户硬隔离 | ✅ 已实现（schema v29） |
| **B4** | 隔离图可复核恢复 / 定向清理 | 误判可回收；按原因批量清理 | ✅ 已实现 restore / purge 接口 |
| **B5** | 基础图库直接产出视频计划 | 选中干净图即可预览分镜，复用现有渲染/草稿链路 | ✅ 已实现 preview-video（桥接 `build_video_plan`） |

**能力边界（明确不做）**：本地质检只到 L4（确定性像素运算）——格式、归一化、近似去重、
质量过滤、主色/底层特征；**不做**产品名/品类/描述/语义标签与分组决策（L5/L6），这些仍归远程
多模态模型。重复判定要求 pHash 与 dHash **同时**命中，避免同一摄影棚背景被误判为重复。

**目录与数据约定**：
- 干净图：`product-library/<uid>/base-library/`
- 隔离图：`product-library/<uid>/quarantine/{corrupt,low_quality,duplicate}/`
- 元数据：`product_library_base_images` 表（状态 ready/quarantined + pHash/dHash/质量分/主色）

**与既有导入的关系**：两条入口并存——目录导入（AI 分组）服务「按产品归档」，基础图库
（本地质检）服务「攒干净图源」。基础图库的 clean 图片可作为未来批量视频生成的输入，
无需先创建产品或走远程识别。

### 4.1 桌面壳启动、登录、形态与功能的六条产品硬约束（红线）

> 状态：**产品硬约束，2026-11-20 补入（S1–S4 同日扩充 S5–S6）**。这六条是桌面客户端
> 「打开即可用、免安装、功能完整」体验的最低标准，任何实现/构建路径都不得违反。
> 历史上多次「跑偏」均因未显式声明本节，故在此固化。判定一个桌面壳是否合格，逐条对照下表。

| 编号 | 硬约束 | 合格判定（可观测） | 不合格表现（禁止） |
|---|---|---|---|
| **S1** | **界面立即打开**：桌面壳进程启动后，窗口马上渲染可直接交互的界面（登录页或对话框），不得被任何前置任务阻塞 | 双击 exe 后在数秒内出现 UI；本地运行时解压、CDN 分片下载、健康检查等待等**全部在 UI 之后或后台**进行，不作为进界面的门槛 | 先显示「正在下载运行时…/正在解压内置环境」进度页、下载完才给界面；健康检查失败时窗口停在空白/状态栏 |
| **S2** | **固定后端 + 微信开放平台登录**：桌面壳固定连接 **`https://ocbot.aixifs.com/videogen`**，登录复用该后端**已实现的微信开放平台网站应用 SSO**（`wechat_open` provider，`open.weixin.qq.com/connect/qrconnect`，scope `snsapi_login`，回调域 `ocbot.aixifs.com`） | 打开即跳到微信官方授权页并签发 JWT；无需用户配置服务器地址、无需本地账号密码登录；**不新造登录**（主干已实现，见下方说明） | 让用户手填后端地址、弹本地注册/密码登录、连非 `ocbot.aixifs.com` 的实例、把后端地址做成可选项、**自绘二维码或另做一套本地登录 UI** |
| **S3** | **无首启引导/无 onboarding 界面**：从打开到进入对话，不出现任何用户引导、安装向导、初始化配置页 | 登录后直达可输入对话框（R5）；缺能力时给的是「功能内提示 + 主动触发入口」，不是全屏引导流程 | 首次启动弹「欢迎使用」多步向导、强制先装环境才能继续、把环境探测做成进界面的必经步骤 |
| **S4** | **依赖环境登录后按需探测/安装**：本机依赖环境（视频渲染 `video-runtime`、便携 Python、可选组件）的探测与安装，**发生在登录之后**，由用户在对应功能里**主动选择触发** | 未登录不探测、不下载；登录后用户点「检测环境/制作视频」等入口才触发探测；探测结果给出可操作的安装引导（如 `environment_install`），失败不阻塞其它功能 | 启动即后台下载 ~290MB 运行时/分片、首启强装 WebView2 之外的组件、缺环境时直接把用户挡在安装页、把下载器/进度面板作为启动第一屏 |
| **S5** | **绿色版交付、免安装、双击即跑**：桌面客户端的默认交付物是**绿色版目录/压缩包**——一个文件夹内含 `Octop.exe` 与其同级的 `video-runtime/`，**双击 exe 直接运行**，不需要 NSIS/安装向导、不写 Program Files、不写注册表、不改系统 PATH | 解压/拷贝到任意目录（含 U 盘）后双击 `Octop.exe` 即可打开界面；搬移/删除整个目录不留系统残留；`video-runtime` 位于 exe 同级并被 `videoRuntimeInstallDir()` 原生识别 | 产出 NSIS 安装器（`*-setup.exe` / `Octop-desktop-windows-*.exe`）、要求「下一步下一步」安装、装到 Program Files、写注册表卸载项；绿色版里缺 `video-runtime` 导致视频不可用 |
| **S6** | **完整功能构建进入**：绿色版必须把**素材管理（含素材库 AI 识别交互入口）**与**视频依赖环境的探测/下载/安装能力**完整构建进去，不得是「只有壳、点进去啥也没有」的空壳 | 构建时烘焙 `VIDEO_COMPONENTS_URL` = **manifest.json URL**（如 `https://dw.mengxa.com/video-components/1.4.0/win-x64/manifest.json`，可逗号分隔多节点），使 `environment_install` 返回真实下载地址而非 `NO_INSTALLER`；绿色版内含/video 功能可就地补齐 `video-runtime`（node + chrome-headless-shell）；素材管理功能入口可用 | 构建留空 `VIDEO_COMPONENTS_URL` 导致「安装环境」报 `NO_INSTALLER`；把 `.exe` 安装包 URL 当 manifest 填进去；绿色版只给裸壳 exe、视频与素材能力缺失 |

**S5/S6 的事实补充（防止把交付形态做偏）**：
- **绿色版是目录，不是安装器**：`videoRuntimeInstallDir()` 优先级为 `OCTOP_DESKTOP_VIDEO_RUNTIME` > `<exe 同级>/video-runtime` > 用户缓存，exe 同级布局是代码原生支持的绿色形态。Taskfile 现有 `package*`/`create:nsis:installer` 三条路径**全部产出 NSIS 安装器**，不满足 S5，绿色版必须走独立的打包路径（裸壳 + 同级 `video-runtime` 目录 → 压缩包），不得复用 NSIS 安装器流程。
- **`VIDEO_COMPONENTS_URL` 必须是 manifest.json，不是安装包 exe**：`video_install.go:104-109` 把该值交给 `bootstrap.LoadManifest` 解析 `parts[]` 逐块下载；填 `.exe` URL 会解析失败。仓库 `docs/desktop-windows-build.md` 里给出的 `Octop-video-components-*.exe` 链接是旧格式，勿用。
- **素材管理走服务端 UI**：素材库前端在 ocbot 服务端已部署，thin 壳登录后即可用（S2/S3），绿色版不另做一套本地素材 UI；但入口与交互链路必须在验收中确认可达。

**S2 的事实补充（防止把登录做偏）**：微信开放平台登录在主干**早已实现**，本次是「复用」不是「新造」。
- 落点：后端 `wechat_open` adapter（`77b1e910`）+ 登录页单一 SSO 入口（`9e33133c`/`8b496018`）；昨天版本（`019c6e00`）与当前代码一致。
- Octop 侧**只有一条入口**：登录按钮 → 开 SSO popup → 跳微信官方 `qrconnect` 授权页 → 微信带 `code` 回调 → 后端换 `openid` 签发 JWT。
- 所谓「扫码登录 / 直接登录」两种状态，是**微信官方授权页**按当前设备的微信登录态自行呈现的（本机微信已登录可快捷授权，否则手机微信扫码）。**Octop 不自绘二维码、不做两套登录 UI、不判断用户用哪种方式**——只消费回调 `code`。详见 [微信开放平台登录](./wechat-open-login.md)。

六条约束的优先级：**S1 > S2 > S3 > S4，且 S5、S6 为交付形态与功能完整性的强制基线**；
相互冲突时以上位约束为准。即「先能打开界面 → 再固定走指定后端登录 → 全程无引导 →
环境按需、登录后、用户主动 → 以绿色版免安装交付 → 素材与视频能力完整构建进入」。

**与 §5 形态的关系**：满足 S1–S6 的默认分发形态是 **thin 内核的绿色版**——UI 走 ocbot 服务端
（满足 S1/S2/S3），壳以「exe + 同级 video-runtime」目录/压缩包交付（满足 S5），
烘焙 manifest URL 使环境下载安装可用（满足 S4/S6）。`full` 内嵌运行时、`slim` 首启下载分片，
二者若把解压/下载放到界面之前即违反 S1/S3/S4，只能作为**离线/内网备选**，且同样必须以绿色版
形态交付（S5）、不得走 NSIS 安装器。`defaultServerURL` 必须烘焙为
`https://ocbot.aixifs.com/videogen`，`VIDEO_COMPONENTS_URL` 必须烘焙为 manifest.json URL（见 §5 决策）。

## 5. 交付形态（产品视角）

Octop 以多种形态交付，选择逻辑与渠道详见 [交付矩阵](./RELEASE-MATRIX.md)。产品侧要点：

| 形态 | 产物 | 面向 | 特点 |
|---|---|---|---|
| **服务端 / Web** | Python wheel + 内置 dashboard SPA | 自托管部署者 | `pip install` 单进程启动 |
| **桌面绿色版（thin 内核）** | **绿色目录/压缩包**：`Octop.exe` + 同级 `video-runtime/` | **默认/唯一主推分发形态** | 双击即跑、免安装、不写系统；UI 走 `https://ocbot.aixifs.com/videogen`，烘焙 manifest URL 使素材/视频能力完整；满足 §4.1 S1–S6 |
| **桌面 full / slim** | 内嵌/首启下载运行时的绿色目录 | 离线 / 内网备选（非默认） | 完整运行时本地化；若解压/下载阻塞开界面则违反 S1/S3/S4；同样免安装（S5）、能力完整（S6） |
| **CLI / API / ACP** | 命令行与接口 | 开发者 | 随 wheel 提供 |

> **不再提供 NSIS 安装器**：`package*` / `create:nsis:installer` 产出的 `*-setup.exe` 不满足 S5，
> 不作为交付物。绿色版压缩包解压即用，用户可整体拷贝/删除，无系统残留。

> 关键产品决策（2026-11-20 修正，以 §4.1 红线为准）：
> **默认/唯一主推分发形态是「thin 内核的绿色版」**——固定连 `https://ocbot.aixifs.com/videogen`，
> 登录走该后端已实现的微信开放平台 SSO，界面立即打开、无引导、依赖按需；
> 以「exe + 同级 video-runtime」目录/压缩包交付，双击即跑、免安装；
> 构建时烘焙 `VIDEO_COMPONENTS_URL`（manifest.json URL）保证素材与视频环境能力完整。
> slim/full 仅作离线/内网备选，**不得作为默认启动路径**，且一律以绿色版交付。
> 运行时分片与视频组件走多节点 CDN，任意两节点失效自动切换可用源。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| **隐私** | 自托管优先，数据留在本地；素材/视频走云端处理时明确边界（AI 识别由服务端调用远程模型） |
| **安全** | JWT 多用户隔离、行级 agent 归属、工具审批、命令护栏、PII 脱敏 |
| **多语言** | 服务端与 dashboard 均支持中英（en/zh） |
| **可靠性** | 登录不被助手创建失败阻断；下载链路支持断点续传、SHA256 校验、多节点 failover |
| **可维护性** | 单一权威文档原则（架构结论固化、避免第二套判定/实现）；活文档随代码更新 |
| **体积** | 运行时分层下载（核心包 + 按需环境包），目标 246 MB → ≤190 MB（依赖瘦身 PR-0 后） |
